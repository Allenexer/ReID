> 本文件回答"做什么、做到什么算成功"。任何影响目标/指标/数据划分的改动，先更新本文件。

## 2. 问题定义

- **任务类型**：图像检索 / 行人重识别（Person Re-Identification）
- **目标**：给定一张（或一组）查询行人图像，在候选图库中按身份相似度排序，让同一 ID 的图片尽量靠前。
- **输入**：query 图像；gallery 图像库。
- **输出**：按相似度降序排列的 gallery 列表，以及 mAP、CMC（Rank-1/5/10）指标。
- **成功标准**：Market1501、Move、CCVID 三个数据集全部成功运行；指标可复现、可溯源；报告完整。
- **课程评分**：成功运行占 50%（三个数据集全跑通有加分）；评价指标占 50%（mAP、Rank-1、Rank-5 正确且高）。

## 3. 数据

| 数据集 | 来源 | 规模/划分 | 角色 | 本地路径 |
|---|---|---|---|---|
| Market1501 | Kaggle（课程给出链接） | 训练 751 ID / 12936 图；测试 750 ID / 3368 query | 主评测集，可训练 | `data/raw/market1501/` |
| Move | 课程提供 | 200 ID / 800 query，含遮挡 | 验证集，仅测试；作业要求修改 test.py 在其上运行 | `data/raw/move/` |
| CCVID | GaitNet-CVPR2019 | 换衣视频 ReID，规模以官方为准 | 探索/加分 | `data/raw/ccvid/` |

规则：

- `data/raw/` 只读；所有转换由 `scripts/` 生成到 `data/processed/`。
- 数据集、压缩包、帧文件一律不入 git；小体积 manifest 可重新生成，默认也不入库。
- 数据来源、下载日期、校验和记录在 `data/README.md`；任何重新划分或版本变化更新登记。
- Market1501 采用官方划分；评测时按惯例剔除同 ID 同摄像头的 gallery 样本。

## 4. 方法与基线

- **主基线**：TransReID（ViT-B/16，ImageNet 预训练 + Market1501 预训练权重），仓库固定 commit。
- **对比基线**：CLIP-ReID（ViT-B/16），仓库固定 commit。
- **加分方向**（对应作业加分项）：
  1. 使用 Market1501 训练集训练并调参（官方给出的参数通常已接近最优，可探索其他配置），
     以自训练模型评测并与官方权重对照——B 主线（训练使用 Colab），C 可并行；
  2. CCVID 换衣场景与 Move 遮挡场景的改进（多帧聚合、TTA、re-ranking、
     遮挡增强等）——C。
- **线性分类器实验**（作业推荐方法 1）：以单张 query 与随机 3 候选输出相似度及
  匹配概率。实现成本低，作为报告的补充实验，由 D 负责，复用 A 的评测工具。
- **不做什么**：从零训练大模型；自建数据集；与 ReID 无关的检测/分割任务。

## 5. 评估

- **主指标**：mAP（mean Average Precision）。
- **辅助指标**：CMC Rank-1、Rank-5、Rank-10。
- **验证协议**：
  - 使用官方 query/gallery 划分；
  - 对每个 query，剔除 gallery 中同 ID 同摄像头的样本后排序；
  - 所有基线使用相同 manifest、相同距离度量（余弦距离，特征已 L2 归一化）；
  - 报告保留 1 位小数，原始值保留 6 位小数。
- **统计要求**：推理基线每个数据集至少完整跑 1 次；训练/调参实验跑 3 个种子，报告均值 ± 标准差。
- **基线验收**：Market1501 上主基线与上游 README 对应权重的报告值相差应 ≤1 个百分点；差距更大时先排查数据、权重和评测协议，再谈调优。

- [ ] 报告完成并经过组内 review

## 7. 约束与风险

- **算力**：RTX 3050 Ti Laptop，4GB 显存。推理可行（建议 batch 16–32）；ViT-B 训练大概率 OOM，训练类实验需 Colab 或缩小模型/分辨率。
- **时间**：课程截止日期 TBD，按 4–5 周排期。
- **主要风险**：
  - Move 数据布局未知，适配器需等数据发布；
  - CCVID 是视频数据，需要抽帧与 tracklet 聚合；
  - 上游代码较旧（Python 3.12 / PyTorch 2.x 兼容问题，已提供补丁）；
  - Google Drive / Kaggle 下载限速或需要账号；
  - 4GB 显存导致 batch 受限，影响调参空间；
  - 若 4 人共用本机，B/C 的推理任务需错峰；各自有机器或 Colab 更稳妥。

## 8. 分工（建议稿）

以下分工是建议，组内可以调整；任务细节由小组在 GitHub Issues 维护。
角色之间不是孤岛，代码需互相 review；一人同时只认领一个进行中任务。
各角色的职责、依据与验收标准按照作业评分设置：成功运行占 50%，指标正确
且高占 50%，加分项为训练调参与难数据集改进。

共享仓库只保留目录结构、角色职责与验收标准；接口、数据结构、命令行与实现均由
各成员自行设计，跨成员使用前由双方协商并记录。

### 8.1 A — 数据与评测

- **职责**：数据集下载、校验与来源记录；manifest 生成（行序与上游实现一致）；
  mAP/CMC 实现并与上游算法对拍；确定跨基线统一评测路径（保存距离矩阵统一重算，
  或对上游日志对拍取证）。
- **依据**：评分的一半取决于指标正确性。全组指标必须由同一套评测代码产出，
  否则两个基线的结果不可比、报告数字无法溯源；manifest 与模型读取顺序不一致
  会导致评测错位。数据与评测是其余工作的基础，其错误会传导至最终成绩。
- **验收**：同一距离矩阵下与上游结果误差 < 0.1%；任何基线的 metrics.json
  均可被统一评测代码复算，或提供对拍记录。

### 8.2 B — TransReID 基线

- **职责**：部署 TransReID 并修改 test.py 以适配课程测试集；在 Market1501 上
  复现官方指标；完成 Move 评测（作业要求 test.py 在课程测试集上可运行）；
  加分项主线——在 Market1501 训练集上训练并调参（本机显存不足以训练 ViT-B，
  训练使用 Colab），以自训练模型评测并与官方权重对照。
- **依据**：TransReID 是主基线，三个数据集可运行占评分大头；训练调参是作业
  明确的加分项，自训练模型若超过官方权重可提高指标得分。
- **验收**：Market1501 指标与官方报告值相差 ≤1pp；Move 产出 metrics.json；
  训练实验提供"自训练 vs 官方权重"的对照结论。

### 8.3 C — CLIP-ReID 与加分项

- **职责**：部署 CLIP-ReID（同样修改 test.py）；CCVID 由单帧基线推进至多帧聚合；
  针对 Move 遮挡与 CCVID 换衣的改进实验；时间允许时同步进行训练调参。
- **依据**：双基线互为印证是报告的基本盘；加分项明确指向 CCVID 与遮挡场景，
  改进实验是提高指标得分的主要空间。
- **验收**：CLIP-ReID 在 Market1501 可复现；CCVID 有可复现结果；每项改进
  均有对照实验与结论。

### 8.4 D — 集成与报告

- **职责**：统一实验入口（干净环境一条命令复现主结果）；线性分类器实验
  （作业推荐方法 1）；图表与报告（数字仅从 metrics.json 生成）；交付打包。
- **依据**：评分中的"成功运行"依赖可复现的入口，复现脚本是验收的直接依据；
  报告数字由脚本生成，避免人工转录错误。线性分类器是作业推荐的方法，
  实现成本低，可作为报告中的补充实验。
- **验收**：干净环境按 README 与 SETUP 可复现主结果；报告中的每个数字可
  溯源至 outputs/ 或 reports/tables/。
